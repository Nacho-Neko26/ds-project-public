# 表情包库（nekowhale 322 张）安装方法

> 先说清楚它是什么：**这不是 DSH 插件，是 qq-agent 桥里的两个文件 + 一个导入脚本。**
> 桥不装插件、零 npm 依赖，所以整套东西就是「导一批图进共享图库 + 一个打分模块 + 四处接线」。
> 想装到别的机器人上也能用，见最后一节。

实测环境：Ubuntu 22.04 / Node 22.20 / qq-agent 桥（/root/qq-agent）/ 322 张 GIF，共 389MB。

---

## 0. 它到底改了哪三样

| 文件 | 作用 |
|---|---|
| `tools/import-nekowhale.mjs` | 拉表情包的元数据，逐张下载 GIF，写进共享图库 `workspace/stickers/_shared.jsonl` |
| `src/sticker-score.mjs` | 按「这一轮对方说了什么」给每张图打分排序（权重移植自上游 `search.ts`） |
| `src/index.mjs` 里四处接线 | 目录构建时用分数挑图、GIF 加 `sub_type:1`、把这轮的话透传下去 |

数据落地：
- 图片：`workspace/stickers/nekowhale/<hash>.gif`
- 索引：`workspace/stickers/_shared.jsonl`（一行一张，行号就是编号：第 n 行 = `S<n>`）
- 台账：`data/sticker-usage.json`（发过哪张，用来避免连着发同一张）

---

## 1. 前置条件

- Node 22（用到内置 `fetch` 和 `WebSocket`，不需要 `ws` 包）
- 桥本身能正常收发消息（G1~G5 都过）
- 磁盘留 500MB（图 389MB + 临时文件）
- 外网能访问 `cdn.jsdelivr.net` 与 `kiriyuki.com`

---

## 2. 放文件

```bash
# 本机 → 服务器（put3 的远端路径是相对 /root 的）
python tmp/put3.py tmp/import-nekowhale.mjs qq-agent/tools/import-nekowhale.mjs
python tmp/put3.py tmp/sticker-score.mjs qq-agent/src/sticker-score.mjs
```

目录不存在先建：`python tools/rc.py "mkdir -p /root/qq-agent/tools"`

---

## 3. 导入表情

```bash
cd /root/qq-agent
node tools/import-nekowhale.mjs --dry   # 先看会加多少
node tools/import-nekowhale.mjs         # 真跑，约 10 分钟
```

输出形如 `{"added":322,"skipped":0,"failed":0,"sharedRows":346}`。
重跑是幂等的（`added:0, skipped:322`），挂了直接再跑一次就行。

脚本行为：
- 元数据优先 `cdn.jsdelivr.net`，失败回落官方 `https://kiriyuki.com/meme/kit/nekowhale.json`
- 图片地址 `https://kiriyuki.com/media/gif/<pack>/<stem>.gif?h=<hash>`
- 每张写入的字段：`hash / emotion / tags / use / en / dir / pack / stem`，外加 `seg.data.summary`（给模型看的短描述）和 `local`（本地路径）
- 根目录可用环境变量覆盖：`QQ_AGENT_ROOT=/opt/qq-bot node tools/import-nekowhale.mjs`

> 走的站点是第三方的，302 跳转和限速都可能变。脚本带 3 次重试 + 800ms 退避；失败会记在 `failed` 里，不中断整体。

## 4. 接线：`src/index.mjs` 四处

**(a) 顶部 import**

```js
import { rankRows as rankStickerRows } from './sticker-score.mjs';
```

**(b) 目录函数签名多一个参数**

```js
function stickerCatalog(key, hintText = '') {
```

**(c) 共享图库改成「先去重去重发，再按分数排」**

真实代码（`src/index.mjs:417-420`）：

```js
const sharedMax = stickerLimit('shared', 16);
let shared = pickFresh(uniqueRows(readJsonl(SHARED_FILE, 2000), stickerKeyOf), usage, now, freshWindowMs);
// 按当前这句话的情绪/场景打分排序（移植 nekowhale 的 search.ts 权重），没查询就退回最近 N 条
if (hintText.trim() && shared.length) shared = rankStickerRows(shared, hintText).slice(0, sharedMax);
```

编号照旧用 `shared[i].index`（原始行号）打标签，`stickerLimit('shared', 16)` 读的是 `config.json` 的 `stickers.sharedCount`。

要点：**先 `pickFresh` 去重去刚发过的，再打分截断**。顺序反了，刚发过的图会被重新排到前面。

**(d) 把这轮对方说的话透传下去**

```js
function stickerHint(key, hintText = '') { ... stickerCatalog(key, hintText) ... }

// handleBatch 里
const hint = stickerHint(session.key, batch.map((m) => m.text || '').join(' '));
```

**(e) GIF 要按表情发**

`materializeSeg()` 里给图片段加一个字段，否则 QQ 里显示成「普通图片」而不是表情：

```js
if (/\.gif$/i.test(p)) seg.data.sub_type = 1;
```

改完必须 `node --check src/index.mjs`，然后 `systemctl restart qq-bridge`（config / 代码都是启动时读）。

## 6. 能调的旋钮

| 想改什么 | 改哪 |
|---|---|
| 打分权重 | `src/sticker-score.mjs` 的 `WEIGHTS`（名字 6 / 标签 5 / 情绪 4 / 文本 4 / 用途 3 / 英文 2 / 方向 2 / 描述 1） |
| 共享图库一次列几张（默认 16） | `config.json` 的 `stickers.sharedCount` |
| 刚发过多久不列 | `config.json` 的 `stickers.freshWindowMs`（默认 25 分钟） |
| 群友发的图多久进打标队列 | `config.json` 的 `expression.memeHub.reviewPoolMinHits`（这台设成 1） |

## 8. 装到别的机器人上

三件东西可以整体搬走，改一处就行：

1. `sticker-score.mjs` 是纯函数（`terms` / `scoreRow` / `rankRows`），**没有任何 QQ 相关依赖**，直接拷。
2. `import-nekowhale.mjs` 只依赖 `node:fs` / `node:path` / 内置 fetch，把 `QQ_AGENT_ROOT` 指到你的工作目录，或者改第 7 行的 `ROOT`。
3. 如果你的机器人不是桥，接线换成「拿到这一轮的文字 → `rankRows(rows, text).slice(0, N)` → 生成编号 → 发图时该平台的 GIF 字段」。

## 9. 常见问题

**发了没反应，接口却回 ok**：看 `data/sticker-usage.json` 有没有新增 hash 键。没有就是没真发出去，查桥日志。

**群里显示成普通图片**：`sub_type:1` 没加上，或者图片不是 `.gif` 后缀。

**老是同一张**：`freshWindowMs` 调大，或确认 `recordUse` 在发送成功后确实跑了。

**索引对不上**：索引是 `_shared.jsonl` 的行号（从 0 数），导出前会先 `uniqueRows` 去重、`pickFresh` 过滤，所以**清单里的 `S<n>` 是原始行号**，不是清单里的第几个。
