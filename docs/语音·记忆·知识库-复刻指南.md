# 复刻指南（二）：语音、记忆、群知识库

> 读者：另一个 AI（或人）。前置条件：**主链路已通**——就是另一份 `QQ接入与服务器部署-复刻指南.md` 的 G1~G5 全绿。
> 这三样都是「主链路之外挂上去的增强」，装法互相独立，可以只挑一样装。
> 占位符：`<QQ号>`、`<服务器公网IP>`、token 之类**都要换成你自己的**。本文不含任何真实账号数据。
> 更新时间：2026-10-25，按当时线上实测核对（版本号、文件字节数、端口、配置键均为实测值）。

---

## 0. 三条线是什么、挂在哪

| 线 | 方向 | 谁在干活 | 端口 | 一句话 |
|---|---|---|---|---|
| 发语音 | 出 | systemd `bailian-tts` + `scripts/tts-service.py` | 3911 | 桥把口语稿 POST 给它，拿回 mp3，NapCat 转 SILK 发出去 |
| 听语音 | 入 | systemd `qq-asr` + `scripts/asr-service.py` | 3912 | NapCat 把语音转 wav → ffmpeg 16k → 本地 SenseVoice 转文字 |
| 长期记忆 | 存 | 插件 `meow-memory`（装在 headless profile 里） | — | 首轮注入长期记忆 + 每条消息按关键词命中 |
| 群知识库 | 存 | 插件 `dsh-knowledge-canvas` | — | 模型自己往 `.dsh-knowledge/group.json` 写群里的梗和称呼 |

三个共同原则，别改：

1. **服务只绑 127.0.0.1**，一个端口都不对外。桥和它们都在这台机器上，不需要公网。
2. **桥对这三个都是「可失败」设计**：TTS 挂了退回 edge-tts，ASR 挂了退回「没听清」，记忆/知识库挂了照常聊天。装的时候也照这个心态——**任何一样起不来都不该阻塞聊天**。
3. 记忆和知识库是**两套东西**，别合并：记忆是「她记得住的人和事」，知识库是「群里长出来的公开梗和称呼」。

## 1. 发语音（TTS，百炼 Qwen-Audio-TTS）

### 1.1 准备：key 和 venv

百炼控制台 https://bailian.console.aliyun.com → 开通 → 拿 API-KEY（就是 DashScope 的 key）。

```bash
apt-get install -y -qq python3-venv python3-pip ffmpeg

# 密钥单独放，600，systemd 用 EnvironmentFile 注入
printf 'DASHSCOPE_API_KEY=sk-你的key\n' > /root/.bailian.env
chmod 600 /root/.bailian.env

python3 -m venv /opt/bailian
/opt/bailian/bin/pip install -q -i https://mirrors.aliyun.com/pypi/simple --upgrade pip
/opt/bailian/bin/pip install -q -i https://mirrors.aliyun.com/pypi/simple dashscope numpy
```

实测可用的版本组合：`dashscope 2.0.1` + `numpy 2.2.6`。`requests` 是 `voice-enroll.py` 用的，顺手装上。

### 1.2 服务契约（`qq-agent/scripts/tts-service.py`）

- 监听 `127.0.0.1:3911`
- `GET /health` → 探活
- `POST /tts`，请求 JSON：

```json
{
  "text": "诶……你咋才回啊",
  "instruction": "像跟朋友打电话一样自然",
  "voice": "音色ID（留空用服务端默认）",
  "emotion": "gentle",
  "intensity": 0.6,
  "rate": 1.0,
  "pitch": 1.0,
  "volume": 50
}
```

- 返回 `audio/mpeg`（**24kHz / 单声道 / 96kbps**，这个采样率是硬要求，见 §1.5）

环境变量（都有默认值）：`BAILIAN_TTS_MODEL=qwen-audio-3.1-tts-flash`、`BAILIAN_TTS_VOICE`、`BAILIAN_TTS_PORT=3911`、`BAILIAN_TTS_RATE=0.88`、`DASHSCOPE_API_KEY`。

### 1.3 systemd（原文照抄）

```ini
# /etc/systemd/system/bailian-tts.service
[Unit]
Description=Bailian TTS local service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
EnvironmentFile=/root/.bailian.env
ExecStart=/opt/bailian/bin/python /root/qq-agent/scripts/tts-service.py
Restart=always
RestartSec=3
User=root

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now bailian-tts
```

**验收**：

```bash
curl -s 127.0.0.1:3911/health
curl -s -o /tmp/t.mp3 -X POST 127.0.0.1:3911/tts \
  -H 'content-type: application/json' \
  -d '{"text":"测试一句，能听见吗","emotion":"gentle"}'
ffprobe -v error -show_entries stream=sample_rate,channels -of default=nw=1 /tmp/t.mp3
# 期望：sample_rate=24000、channels=1；文件能正常播放
```

### 1.4 桥侧接线（`config/config.json` 的 `voice` 块）

```json
"voice": {
  "enabled": true,
  "style": "bailian",
  "dir": "/root/napcat/data/voice",
  "containerDir": "/app/voice",
  "maxChars": 60,
  "maxSeconds": 10,
  "bailian": {
    "url": "http://127.0.0.1:3911/tts",
    "voice": "你的音色ID",
    "timeoutMs": 30000,
    "padTailSeconds": 0.5,
    "rate": 1,
    "pitch": 1,
    "loudness": "",
    "defaultInstruction": [
      "像跟朋友打电话一样自然，说到要紧的词慢一点、重一点，别匀速念稿",
      "日常聊天的语气，有轻有重、有快有慢",
      "放松地说，带点情绪，不要从头到尾一个调子"
    ],
    "instructions": { "困": "" },
    "emphasis": true,
    "pauses": true,
    "balance": false
  }
}
```

`dir` 是宿主机目录，`containerDir` 是容器内同一目录——compose 里必须有 `./data/voice:/app/voice` 这条挂载，否则声音文件 NapCat 读不到。

模型输出协议（写在人设里，桥负责解析，指令行本身不会发出去）：

```
__VOICE_META__ {"emotion":"gentle","intensity":0.6,"scene":"凌晨一点，窝在被窝里"}
__SEND_VOICE__ 诶……<emphasis>你咋才回</emphasis>啊……我都等半天了
```

- `emotion` 只认 9 个：`happy/sad/surprised/gentle/calm/confused/encouraging/sleepy/soft`
- **停顿用「……」**，不要用 `<break>`（这条接口不按毫秒兑现标签，拼段还有接缝感）
- `<emphasis>` 有效，必须保留在文本里交给模型原生处理，**别在 strip_tags 时剥掉**

降级链路：`bailian` 失败 → `plain`（edge-tts，venv `/opt/tts`）。所以 `/opt/tts` 里也要装一份 `edge-tts` 兜底。

### 1.5 自建音色（复刻本人原声）

录音要求：**10~20 秒最合适**（最长 60 秒）、WAV/MP3/M4A、≥16kHz、单人、无 BGM、不是唱歌。

```bash
# 在服务器上跑，自动读 /root/.bailian.env
python3 qq-agent/scripts/voice-enroll.py create /root/ref.mp3 --prefix mingyue
python3 qq-agent/scripts/voice-enroll.py list
python3 qq-agent/scripts/voice-enroll.py delete <voice_id>
```

拿到 `voice_id` 填进 `config.voice.bailian.voice` → `systemctl restart qq-bridge`（桥每次启动读一次 config；改人设不用重启）。

注意：
- 音色**绑死在创建时的 `target_model` 上**（现在 `qwen-audio-3.1-tts-flash`），换模型必须重建。
- 音色**按账号隔离**：别人的 `xxx-bailian-<hash>` 调不通，报 `Engine error [411]`。
- 建音色免费，合成按模型计费；一个账号上限 1000 个。

### 1.6 音频后处理链（`tts-service.py` 的 `pcm_to_mp3`，原样保留）

```
equalizer=f=5200:t=q:w=1.2:g=-4   # 削固定尖峰（齿音）
lowpass=f=6800:poles=2            # 切高频嘶声
volume=3dB
alimiter=limit=0.708:level=false  # 峰值留 −3dBFS 余量
→ libmp3lame 96k，-ar 24000，单声道
```

这条链是听感定稿，**不要再叠 `loudnorm`**。要更响只走 `loudness: "loud"`（现在关着），别两套一起上。

### 1.7 坑（TTS 专属）

| 现象 | 根因 | 做法 |
|---|---|---|
| QQ 里听着破/劈 | 输出 16kHz，NapCat 又转 24kHz，白丢 8~12kHz | 直接出 24000Hz，零重采样 |
| `Engine error [411]` | 音色 ID 不在自己账号下 | `voice-enroll.py list` 对一遍 |
| 改 `pitch` 没变化，或者一下变很闷 | 这接口对 `pitch_rate` **分档量化**，0.98/0.96/0.95 生成同一份文件 | 要么 1.0，要么直接跳到 0.93/0.90 |
| 声音发飘/有波动 | 两道 loudnorm 叠加（服务端 + 桥端） | 只留一条，现在两条都关 |
| 太激动容易破 | `happy` 曾被映射成 `[excited]`（f0 +18%、响度 +21%） | happy 不带标签，只轻微提速 |
| 停顿时长不受控 | `<break time>` 不被当真 | 用「……」，或整段一次合成 |
| 语音发不出去 | 人设里写了「心情必须高兴」之类的门槛 | 删掉门槛，改成「主人点名要语音就照办」 |
| NapCat 读不到 mp3 | compose 少挂 `./data/voice:/app/voice` | 补挂载并重启容器 |

## 2. 听语音（ASR，SenseVoice + sherpa-onnx，纯本地）

### 2.1 模型（只下两个文件，别下整包）

GitHub release 的整包 **1,047,870,769 字节**（约 999MB）还限速到 ~30KB/s，不要用。直接取 int8 版本：

```bash
DIR=/opt/asr/models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17
mkdir -p "$DIR"
# model.int8.onnx 实测 239,233,841 字节；tokens.txt 实测 315,894 字节
curl -fL --retry 3 -o "$DIR/model.int8.onnx" \
  https://hf-mirror.com/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/resolve/main/model.int8.onnx
curl -fL --retry 3 -o "$DIR/tokens.txt" \
  https://hf-mirror.com/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/resolve/main/tokens.txt
ls -l "$DIR"
```

模型覆盖 中/英/日/韩/粤，int8 约 229MB，加载 ~1.1 秒，5.35 秒语音转写 ~264ms。

### 2.2 venv

```bash
python3 -m venv /opt/asr
/opt/asr/bin/pip install -q -i https://mirrors.aliyun.com/pypi/simple --upgrade pip
/opt/asr/bin/pip install -q -i https://mirrors.aliyun.com/pypi/simple sherpa-onnx numpy
# 实测：sherpa_onnx 1.13.8（+ sherpa-onnx-core 1.13.8）、numpy 2.2.6
```

### 2.3 服务契约（`qq-agent/scripts/asr-service.py`）

- 监听 `127.0.0.1:3912`，环境变量 `ASR_MODEL_DIR`、`ASR_PORT`
- `GET /health` → `{"ok":true,"model":"...","loadMs":...}`
- `POST /asr` 三种入参，任选：
  - `content-type: application/json` + `{"path": "/abs/a.wav"}`（服务端自己读文件）
  - `content-type: application/json` + `{"b64": "..."}`
  - 直接把 wav 字节放 body（桥用的就是这种）
- 返回 JSON，字段是转写结果（桥取文本）

### 2.4 systemd（原文照抄）

```ini
# /etc/systemd/system/qq-asr.service
[Unit]
Description=Blue Whale ASR (SenseVoice, local)
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/qq-agent
Environment=ASR_MODEL_DIR=/opt/asr/models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17
Environment=ASR_PORT=3912
ExecStart=/opt/asr/bin/python /root/qq-agent/scripts/asr-service.py
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now qq-asr
```

**验收**：

```bash
curl -s 127.0.0.1:3912/health          # ok:true，loadMs 一千上下
ffmpeg -y -v error -i /root/ref.mp3 -ar 16000 -ac 1 -c:a pcm_s16le /tmp/a.wav
curl -s -X POST 127.0.0.1:3912/asr \
  -H 'content-type: application/json' -d '{"path":"/tmp/a.wav"}'
# 期望：转写文本和录音内容一致
```

### 2.5 桥侧接线（`config/config.json` 的 `asr` 块）

```json
"asr": {
  "enabled": true,
  "url": "http://127.0.0.1:3912/asr",
  "timeoutMs": 25000,
  "maxSeconds": 120,
  "ffmpeg": "ffmpeg"
}
```

链路（`src/asr.mjs`）：QQ 语音是 **SILK**（`#!SILK_V3`），系统 ffmpeg 解不了 → 让 NapCat 自己转 `get_record out_format=wav` → ffmpeg 转 16k 单声道 wav → POST 本机 ASR → prompt 里出现 `[语音转写：……]`。
任何一步失败都只退化成「对方发了段语音，你没听清」，**不影响回复**。

### 2.6 坑（ASR 专属）

| 现象 | 根因 | 做法 |
|---|---|---|
| `AttributeError: sherpa_onnx has no attribute read_wave` | sherpa-onnx 1.13 没有这个 API | 服务里用标准库 `wave` + numpy 自己读 wav（已在 asr-service.py 里） |
| 下载模型卡在 30KB/s | 下的 GitHub 整包 | 换 hf-mirror 只取 int8 两个文件 |
| ffmpeg 报 `Invalid data found` | 直接喂了 SILK 文件 | 必须先让 NapCat `out_format=wav` |
| 转写慢/超时 | 语音太长 | `maxSeconds: 120`，超过直接不转 |
| 服务起来就 OOM | 3.5G 内存里同时跑 NapCat + TTS + 模型 | 加 2G swap；或改用更小模型 |

## 3. 长期记忆（meow-memory 插件）

### 3.1 装

```bash
# profile 不存在先建（见主指南 §4.4）
dsh plugin --profile headless add meow-memory
```

装完打开 `/root/.dsh/profiles/headless/package.json`，**确认两处都有**：

```json
"dependencies": { "meow-memory": "^0.31.1" },
"dsh": { "profile": { "bundles": [
  "@deepseek-ai/dsh-base", "@deepseek-ai/dsh-headless",
  "dsh-selfwake", "@liustack/modlens", "dsh-knowledge-canvas", "meow-memory"
] } }
```

只装依赖、不列进 `bundles` = 没挂上。桥每轮起一个新的 `dsh` 进程，所以**改完不用重启桥**，下一条消息就生效。

### 3.2 数据在哪

| 文件 | 内容 |
|---|---|
| `/root/qq-agent/workspace/.dsh-meow/memory.db` | SQLite，七张内容表：`soul / user / project / fact / lesson / topic / rules` |
| `/root/qq-agent/workspace/.dsh-meow/sessions/` | 会话账本（dream、窗口记录） |
| `/root/qq-agent/workspace/.dsh-meow/dream-debug.log` | 自动整理（dream）的调试日志，排查「为什么记不进去」看这里 |

注意：`memory.db` 在 **workspace 里**（不是 `~/.dsh`），所以跟着 workspace 一起备份/同步；`~/.dsh/profiles/headless/node_modules` 是插件代码，不用搬。

### 3.3 行为

- 每次会话**首轮**注入长期记忆（user/rules 那几层全量，其余按需）。
- 之后每条消息**按关键词命中**补注入。
- 模型自己决定要不要写；写的时候按 level 分表（`fact` 一句话、`lesson` 经验、`project` 带子标签）。
- 桥自己还有一套**速记**（`workspace/memory/memories.jsonl`），每 60 条消息自动学一次，注额度 350 字（`config.memory.injectChars`）。两套**不互相导入**，别删 jsonl——自动学习还靠它。

### 3.4 验收

```bash
DB=/root/qq-agent/workspace/.dsh-meow/memory.db
sqlite3 "$DB" ".tables"
sqlite3 "$DB" "select level, count(*) from memories group by level;"
```

表结构可能随插件版本变，先 `.tables` 看实际表名。判别「插件真的在跑」的更强证据：在 QQ 里聊两句，然后

```bash
sqlite3 "$DB" "select substr(content,1,40), datetime(updated_at) from memories order by updated_at desc limit 5;"
```

出现新条目 = 通了。

### 3.5 坑

| 现象 | 根因 | 做法 |
|---|---|---|
| 聊天时明显没有记忆感 | 插件装了但没进 `bundles` | 对 `package.json` 的 `dsh.profile.bundles` |
| 每轮变慢、更贵 | `injectChars` 调太大 | 保持 350 上下；注入是每轮成本 |
| 记忆写了两份、内容重复 | 有人把 jsonl 导进了 memory.db | 两套各管各的，别再导入第二遍 |
| 换机器后记忆没了 | 只搬了代码没搬 `workspace/.dsh-meow` | 备份 workspace |

## 4. 群知识库（dsh-knowledge-canvas 插件）

### 4.1 装

```bash
dsh plugin --profile headless add dsh-knowledge-canvas
# 同样要确认它在 dsh.profile.bundles 里（实测版本 ^0.4.5）
systemctl restart qq-bridge
```

### 4.2 文件结构（`/root/qq-agent/workspace/.dsh-knowledge/`）

```json
group.json        // 库本体：库「群里的新知识」
selection.json    // {"version":1,"enabled":["group"]} ← 决定注入哪些库
welcome.json      // 内置教程库（示例，可以关掉）
layout.json       // 画布布局，插件自己维护
activity.log      // 每次 knowledge_read / knowledge_write_node 一行（排查第一现场）
```

`group.json` 的节点结构（手改前先备份）：

```json
{
  "version": 1, "id": "group", "name": "群里的新知识",
  "nodes": [{ "id": "k1", "parent": "root", "title": "...", "body": "...", "change": "new", "at": 1690000000000 }],
  "links": []
}
```

推荐骨架：`k1` 根（规则与边界）→ `k2` 怎么写一条 / `k3` 群友的称呼与外号 / `k4` 群里的梗。模型新写的挂到对应伞节点下。

### 4.3 **最关键的一步：光装插件，模型不会写**

这是实测踩过的坑：插件给了工具，但模型不知道自己「该」用它。必须在 `src/agent.mjs` 的群聊分支 `rules.push(...)` 里**明确点名**：

- 用哪个库：`base="group"`
- 什么时候写：群里出现新梗、新外号、口头禅、内部约定
- 写什么格式：一条标题 + 正文 + 「什么时候该想起它」
- 两条红线：**不记联网查到的资料/通用知识/教程**；不记一次性闲聊

改完 `node --check src/agent.mjs` → 上传 → `systemctl restart qq-bridge`。

### 4.4 验收（看 activity.log，别看猜）

```bash
tail -20 /root/qq-agent/workspace/.dsh-knowledge/activity.log
# 每行一次读写：session id / 操作 / 耗时 / 字符数
sqlite3 不适用；直接数节点：
python3 -c "import json;d=json.load(open('/root/qq-agent/workspace/.dsh-knowledge/group.json'));print(len(d['nodes']))"
```

在群里聊出一个新梗（或自己说一句「这个记下来」），过一两轮再看节点数有没有涨。**涨了才算通。**

### 4.5 坑

| 现象 | 根因 | 做法 |
|---|---|---|
| 插件装了，库里一直空 | prompt 没点名要它写 | 见 §4.3，引导必须写进 `agent.mjs` |
| 模型把联网资料也写进去 | 红线没写清楚 | 明确「只记群里长出来的」 |
| 换了库不生效 | `selection.json` 没改 / 桥没重启 | 改 `enabled` 后 `systemctl restart qq-bridge` |
| 手改 `group.json` 后插件报错 | 少了 `version/id/nodes/links` 字段 | 按 §4.2 的结构补，改前先 `cp` 备份 |
| 两端的库内容互相覆盖 | 同步时把 `selection.json` 也搬了 | 那是各端本地配置，**不搬** |

## 5. 三条线一起上了之后，一轮消息长什么样

```
QQ 来一句话（文字/图片/语音）
   │
   ├─ 语音？→ NapCat get_record wav → ffmpeg 16k → POST :3912/asr → [语音转写：…]
   ├─ 图片？→ 桥自己读图/落盘，写进 prompt
   ▼
拼 prompt：人设 + 最近上下文 + 记忆注入（meow-memory）+ 知识库注入（group）+ 素材清单
   ▼
dsh --profile headless --patch 人设补丁 "<prompt>"     ← 一次调用
   ▼
模型输出里可能带：<SKIP> / __SEND_STICKER__ / __SEND_VOICE__ / __KNOWLEDGE 写入调用
   ▼
桥按指令执行：发文字、发表情、合成语音（:3911）、写知识库
```

耗时参考（云上 2 vCPU）：纯文字 2.8~3.6 秒；带语音合成 +1~2 秒。

## 6. 出问题先看哪里

```
她说「听不见」/对方语音没转文字
├─ curl 127.0.0.1:3912/health 不通 → systemctl status qq-asr；journalctl -u qq-asr -n 50
├─ 通但转写空            → 模型文件不全（model.int8.onnx / tokens.txt）
└─ 日志报 ffmpeg         → 拿到的是 SILK，不是 wav

语音发不出来
├─ curl 127.0.0.1:3911/health 不通 → 看 bailian-tts 日志 / key 是否 401
├─ 服务好但 QQ 没声音    → compose 的 ./data/voice 挂载 + config.voice.dir
└─ 声音怪               → pitch/rate/loudness 是不是被动过；采样率是不是 24k

记忆没感觉
├─ 插件在不在 bundles → package.json
└─ 库有没有新条目      → sqlite3 memory.db

知识库一直是空的
├─ selection.json enabled 有没有 "group"
├─ agent.mjs 群聊分支有没有点名 knowledge_write_node
└─ activity.log 有没有行
```

## 附：这三样一共多了什么

```
/opt/bailian/            TTS venv（dashscope + numpy）
/opt/asr/                ASR venv（sherpa-onnx + numpy）+ models/
/opt/tts/                edge-tts 兜底（可选）
/root/.bailian.env       百炼 key（600）
/etc/systemd/system/bailian-tts.service
/etc/systemd/system/qq-asr.service
/root/qq-agent/workspace/.dsh-meow/        记忆库
/root/qq-agent/workspace/.dsh-knowledge/   知识库
/root/qq-agent/scripts/{tts-service.py,asr-service.py,voice-enroll.py}
```

内存占用参考：NapCat ~250MB、桥 ~80MB、TTS ~120MB（按需起）、ASR ~600MB（常驻模型）。2G 内存的机器上 ASR 和 TTS 同时跑会吃紧，3.5G + 2G swap 是实测能稳住的下限。
